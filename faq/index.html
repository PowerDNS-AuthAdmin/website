FAQ

PowerDNS-AuthAdmin questions, answered

Installation, supported PowerDNS versions, single sign-on, permissions, clusters, reverse DNS, zone monitoring, AI assistants over MCP and security. Can't find what you need? Ask in GitHub Discussions.

What is PowerDNS-AuthAdmin?

PowerDNS-AuthAdmin is a free, open-source web interface for managing PowerDNS Authoritative servers. It adds role-based access control, single sign-on (OIDC, SAML and LDAP), passkeys and MFA, a diff-before-apply record editor, automatic PTR maintenance with a fleet-wide Reverse DNS report, Zone Monitoring of delegation, nameservers and DNSSEC from the outside, DNSSEC and TSIG management, multi-backend cluster support, an append-only audit log and a built-in MCP server for AI assistants on top of the PowerDNS HTTP API. It ships as one Docker image and is MIT licensed.

Is PowerDNS-AuthAdmin free?

Yes. PowerDNS-AuthAdmin is free and open source under the MIT licence. You self-host it on your own infrastructure; there is no SaaS, no account to create and no telemetry.

Which PowerDNS versions does it support?

PowerDNS-AuthAdmin is tested in CI against PowerDNS Authoritative 4.6 to 5.1 (4.6, 4.7, 4.8, 4.9, 5.0 and 5.1). It talks to PowerDNS through the Authoritative server's built-in HTTP API, so the API and an API key must be enabled. Catalog zones need PowerDNS 4.7 or later, and on 5.1 editing LUA records needs enable-lua-record-updates=yes.

Does it work with PowerDNS Recursor or dnsdist?

No. PowerDNS-AuthAdmin manages PowerDNS Authoritative servers, the ones that host your zones. It does not configure PowerDNS Recursor or dnsdist.

How do I install PowerDNS-AuthAdmin?

Run the Docker image ghcr.io/powerdns-authadmin/powerdns-authadmin with Docker Compose. Generate APP_SECRET_KEY and APP_ENCRYPTION_KEY once into a .env file, set APP_URL to the URL your browser uses, set the bootstrap admin account and start the stack. Migrations run automatically on boot. The installation guide covers production setups with TLS and backups.

Which database does it need?

SQLite for a single instance (homelab, evaluation, small teams) or PostgreSQL for multiple instances. To run more than one replica you need PostgreSQL plus Redis, which coordinates rate limiting, one-time reveal tokens and live updates across replicas.

Which single sign-on providers are supported?

Any OpenID Connect provider (with PKCE, group → role mapping and RP-initiated logout), any SAML 2.0 identity provider such as AD FS, Authentik, Keycloak, Okta, Microsoft Entra ID, PingFederate or Shibboleth, and LDAP against Active Directory or OpenLDAP. Local email and password accounts are also available.

Does it support passkeys and two-factor authentication?

Yes. Users can enrol WebAuthn passkeys and hardware security keys such as YubiKey, either for passwordless sign-in or as a second factor, and TOTP authenticator apps. A role can be marked MFA-required so everyone holding it must enrol.

Can I give a customer or team access to only their own zones?

Yes. Every role assignment has a scope: global, a team, a single zone or a single server. A user can hold a record-editing role on one zone and have no access anywhere else, assigned by an administrator or mapped from an identity provider group. The SOA, apex NS records and zone settings are separate permissions, so you can let someone manage records without letting them change the zone's authority.

Can it manage several PowerDNS servers or clusters?

Yes. One install manages standalone primaries, primary + secondaries groups and multi-primary clusters that share a replicated database. Zones from all backends appear in one list, and sync probes show whether every secondary or cluster peer has the same serial and records.

Can PowerDNS-AuthAdmin keep PTR records in sync?

Yes, since version 1.10.0. With automatic PTR maintenance on, saving or deleting an A or AAAA record also creates, updates or removes the matching PTR in a reverse zone hosted on any of your backends, including RFC 2317 classless zones, and the review dialog shows the reverse change before you save. Turn it on globally with the auto_ptr setting, per zone with X-AUTHADMIN-AUTO-PTR metadata, or for one save with the editor's checkbox; nothing is written otherwise. It never creates reverse zones and never replaces a PTR that points at another name without an explicit takeover. To reconcile what is already there, set REVERSE_DNS_ENABLED=true for the Reverse DNS report, which compares every A/AAAA record in the fleet with its PTR (OK, missing, mismatch, ambiguous, orphan, not hosted) and rectifies the rows you pick after showing the PTR diff. See the feature reference.

Does it monitor delegation, nameservers and DNSSEC?

Yes, since version 1.10.0, when you set ZONE_MONITOR_ENABLED=true. Zone Monitoring checks every hosted zone from the outside on a schedule: the delegation at the parent, read by walking from the root servers rather than through a resolver, each nameserver's reachability, authority, serial and NS set, open AXFR, the DS at the parent against the zone's DNSKEYs, what public or internal resolvers answer, and the SOA timers, MNAME and RNAME. Findings have stable codes, a severity and what to do; errors and warnings appear in the notification bell, and an SOA MNAME finding has a Fix button that shows the change as a diff before saving. It is off by default because it sends DNS queries outside your network. See the feature reference and the configuration guide.

Can I search across every zone and record?

Yes. Press Ctrl K (⌘K on a Mac), / or the Search button in the header to fuzzy-search zones, records (names and values) and configuration across every backend. The PowerDNS request log and the audit log are searched from their own tabs. Results are filtered by your own permissions and secrets are never indexed or returned. The same search is available as GET /api/search and the MCP search tool.

Is there an API for automation?

Yes. Every admin screen has a matching /api/admin route. Scripts authenticate with personal access tokens (pda_pat_…) that carry their own permission scopes, sent as a Bearer token or X-API-Key header. The same tokens authenticate MCP clients on /api/mcp, and DNSSEC state (signing status, keys, the DS set, per-mirror sync) is readable over the API too.

Can I manage DNS with Claude Code or another AI assistant?

Yes. Since version 1.9.0, PowerDNS-AuthAdmin includes a Model Context Protocol (MCP) server at /api/mcp. Connect Claude Code, Codex, Cursor, Windsurf or any MCP client over Streamable HTTP with a personal access token as the Bearer header, then ask in plain language: point www at an address, replace a zone's MX records, create a staging zone. The assistant gets tools for backends, zones and records, and since 1.10.0 for everything the new pages do: finding a zone, checking a name before adding it, waiting for a zone to sync, the Reverse DNS report and its rectify, Zone Monitoring, search and notifications. See the MCP guide for each client's configuration.

Is it safe to let an AI assistant change DNS records?

The MCP server gives an assistant no power its token owner doesn't have. Every call runs as the owner of a personal access token, limited by the token's scopes and per-zone grants, and goes through the same validators, optimistic concurrency and audit log as the web UI. A read-only token presents a read-only server, destructive tools are annotated so clients can ask for confirmation, deleting a zone requires the assistant to repeat its name, and every change is logged under the owner's name with the client's user agent. Give a bot the minimum: a per-zone grant beats a global role.

Can I import existing zones?

Zones already hosted in PowerDNS appear as soon as you register the backend, because PowerDNS-AuthAdmin reads them straight from the PowerDNS API. You can also import one or many zones from a BIND zone file, and export any selection of zones as a BIND-format bundle.

Does PowerDNS-AuthAdmin send telemetry or load anything from a CDN?

No. It makes no phone-home calls and serves all of its assets itself, so it runs in air-gapped networks. The only features that send traffic outside your network on their own are Zone Monitoring (ZONE_MONITOR_ENABLED=true) and the Reverse DNS lookups for addresses you don't host (REVERSE_DNS_ENABLED=true). Both are off by default, and both send only DNS queries on port 53.

How is it different from PowerDNS-Admin?

PowerDNS-AuthAdmin is a separate project written from scratch in TypeScript on Node.js. Its focus is teams running multiple backends: scoped RBAC, OIDC / SAML / LDAP with group mapping, passkeys, diff-before-apply editing, cluster and secondary sync probes, automatic PTR maintenance, Zone Monitoring, an append-only audit log and a built-in MCP server for AI assistants. See the comparison page for details.

Is there a live demo?

Yes. demo.powerdns-authadmin.org is a real, seeded install you can click around in. The sign-in details are on its login page and in the project README.

Is commercial support available?

Yes. PowerDNS-AuthAdmin is free and community supported: ask questions in GitHub Discussions and report bugs in Issues. Commercial support, 24 hours a day, is available from Next Generation Networks (NGN), the Sydney IT company that built this website; see commercial support for how to reach them.

How do I report a security issue?

Please report vulnerabilities privately through GitHub's private vulnerability reporting, as described in the security policy. Do not open a public issue.
